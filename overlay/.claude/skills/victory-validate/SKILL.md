# Validation
Follow AGENTS.md. Validate the private fork's local baseline and exact branch/head, approved scope and local policy. Public upstream Marvisak/VIctory is only a read-only comparison; do not switch to its checkout or sync automatically. Preserve all user data. Run the independent regression test before and after where feasible. Run both Clippy commands and full tests from current CI; record exact counts and exits, including hardware skips and pre-existing failures.
Build release separately from diag. Compare identical authorized test workloads, inputs, resolution, console mode, driver and duration, with matched cache warmth and isolated external saves/cache. Repeat enough times to distinguish run-to-run variation; use median/range if enough samples. Separate diagnostic and performance runs. Stop at GPU resets, unsafe commit charge or excessive memory pressure. Report time to milestone, frames/presents, visible correctness (human-verified or permitted synthetic evidence), errors, memory and GPU timing where available. No performance claim from a skipped workload.
Run cargo xtask policy and git diff --check; inspect scope and staged paths. Never commit game data, raw logs or derived assets. Draft an English PR summary: root cause, correction, actual validation, commands and hardware, what was not tested, limitations and AI use. Do not invent results, push, commit or publish without approval. Confirm the intended destination and reviewed sanitized diff before any publication; never expose private fork history or fork-only tooling to upstream. If the fix fails or regresses, report it and recommend next steps instead of claiming success.
